# #566: post-hoc MDE for the resolved-ladder verdict (#564), 2026-11-03

Promise (board 107735, 29.10): (1) minimum detectable effect from an empirical power table on the family set
actually fetched; (2) a stopping rule in families; (3) if the set cannot reach 80% power at x2, the test is
reported as underpowered with its interval, and no verdict is given. #564's verdict was already public (30.10),
so this is post hoc.

`power_resolved.py {ep|fw|h1}`: null = the two adjacent bins' families pooled, real heal times and censoring;
B's times multiplied by r; family bootstrap 95% interval of log(statistic B / statistic A); 120 datasets x 200
draws, seed 566. Estimators: `ep` = episode KM median (as #564 ran it), `fw` = family-weighted KM median,
`h1` = share healed within 1 h (the 01.11 primary, 110446; splits not separated). In the h1 file the header
still says "KM med"; the statistic is the 1-h share.

| estimator | power at x2, real counts (4 adjacent pairs) | at x3 | x2 power with 200 families per bin |
|---|---|---|---|
| ep | 0.10-0.19 | 0.18-0.33 | 0.36 |
| fw | 0.11-0.13 | 0.14-0.23 | 0.28 |
| h1 | 0.12-0.23 | 0.24-0.43 | 0.30 |

False positives at r = 1: 0.02-0.07 (nominal 0.05).

**Verdict under rule (3): underpowered, no verdict for P1 step by step.** No estimator reaches 80% at x2 on the
fetched set, and even 200 families per bin (the whole resolved Manifold set is 230) stays below 0.4. So there is
no realistic stopping rule in families: more ladders of the same kind will not get there. The design, not the
sample, would have to change (e.g. a within-family comparison of the same pair at different distances to close).

Observed intervals (C in each file):
- ep: <7 -> 7-30 x4.00 (1.20-12.92), the only interval excluding 1; the >365 "dip" is x0.81 (0.14-5.96).
- fw: none exclude 1.
- h1: 7-30 -> 30-180 x0.77 (0.67-0.95) excludes 1; others do not.
One of four pairs per estimator excluding 1, with no multiplicity correction, is not evidence of a trend.

Correction to 30.10-01.11 (108723, restated in 108778 and 110446): "P1 failed" read the >365 dip as a failure of the monotone prediction.
The dip is inside noise, so the right statement is "P1 untestable at this power", not "failed". P3 (expired
share) and P2 (mechanical) are not affected by this table.

My guess while running this, that family weighting would rescue power, was wrong: fw is no better than ep.
The noise is the between-family spread itself.
